# Календарь Mail в GPT

Отдельное подключение календаря Mail.ru / Mail для бизнеса к ChatGPT Work.
Сервер использует CalDAV-провайдер «Чайки», но не запускает Telegram-бота,
не читает его `.env` и не меняет его `logs/users.json` или подписки.

## Что можно спросить

- «Что у меня завтра? Найди ссылку на созвон».
- «Когда на этой неделе есть час между 10 и 19?».
- «Найди встречи, где обсуждается релиз».
- «Создай встречу “Обсуждение релиза” завтра с 15:00 до 16:00».
- «Покажи непринятые приглашения. Прими вот это».

Версия 0.1 читает встречи, ищет свободные окна, создаёт обычные события и меняет
ответ на приглашение. Перенос и удаление событий, приглашение участников и создание
повторяющихся встреч пока не поддерживаются. Ответ на повторяющееся приглашение
затрагивает всю серию и требует разрешения именно на серию.

## Подготовка сервера

Из корня репозитория с установленными зависимостями:

```bash
venv/bin/python -m satellite.mail_calendar_mcp init \
  --login aleksandr.petrov@vk.team \
  --base-url https://cassinilab.ru/mail-calendar
venv/bin/python -m satellite.mail_calendar_mcp serve
```

Укажите свой HTTPS-адрес, при необходимости с отдельным путём. `init` создаёт отдельный
`logs/mail-calendar/.env` с новым ключом шифрования и разрешённым адресом Mail.
При существующем `.env` команда завершается ошибкой, сохраняя прежний ключ.
Для локальной проверки можно пропустить `--base-url`: будет использован
`http://127.0.0.1:8765`. Локальный HTTP-адрес не подходит для прямого подключения
из облачного GPT.

Сервисные данные находятся в `logs/mail-calendar/`: зашифрованные credentials в
`users.json`, зашифрованные OAuth-клиенты и токены в `oauth.sqlite3`, ключ в `.env`.
Сохраните резервную копию всех трёх файлов вместе. Утеря ключа потребует нового
подключения. Не включайте эти файлы в пакет плагина.

Конфигурация: `MCP_BASE_URL` — публичный HTTPS-адрес сервиса, например
`https://cassinilab.ru/mail-calendar`; `MCP_ALLOWED_LOGINS` —
разрешённые email через запятую; `MCP_TIMEZONE` — часовой пояс IANA;
`MCP_HOST` / `MCP_PORT` — адрес прослушивания; `MCP_DATA_DIR` — каталог данных;
`MCP_ENCRYPTION_KEY` — отдельный Fernet-ключ. Переменные окружения имеют приоритет
над отдельным файлом конфигурации.

## Запуск рядом с «Чайкой»

На 30 сентября 2026 сервис развёрнут на сервере «Чайки» по адресу
`https://cassinilab.ru/mail-calendar/mcp`. Каталог сервиса —
`/opt/mail-calendar/source`, compose project — `mail-calendar`, контейнер —
`mail-calendar-mail-calendar-1`. Он автоматически запускается после перезагрузки.
Публичные маршруты добавлены отдельным include
`/etc/nginx/snippets/mail-calendar.conf`; прежний конфиг сохранён в
`/opt/mail-calendar/backups/cassinilab.ru.before`. Обновление TLS выполняется
существующим certbot для cassinilab.ru. Доступ разрешён владельцу
`aleksandr.petrov@vk.team`; сам календарь подключается через OAuth-страницу.

Готовый отдельный compose: `deploy/mail-calendar/docker-compose.yml`.
Он запускает тот же Python-код отдельным процессом и публикует порт 8765 только
на loopback хоста. Telegram-токен ему не нужен.

Подготовьте каталог для пользователя контейнера. UID получите из собранного
образа, не угадывайте его:

```bash
docker compose -f deploy/mail-calendar/docker-compose.yml build
docker run --rm --entrypoint id satellite-mail-calendar:local -u satellite
```

Выдайте этому UID права на `logs/mail-calendar`, сохранив права `.env` 600 и
каталога 700. Затем:

```bash
docker compose -f deploy/mail-calendar/docker-compose.yml up -d
```

Для размещения на существующем HTTPS-сайте добавьте
`deploy/mail-calendar/nginx-path.conf.example` в его HTTPS server block.
Этот вариант использует отдельный раздел `/mail-calendar` и сохраняет адреса
«Чайки» и основного сайта. Для отдельного домена без пути используйте
`deploy/mail-calendar/nginx.conf.example`. Сохраняйте исходный `Host` и `Origin`:
сервер проверяет их. OAuth discovery находится в `/.well-known/` корня сайта,
OAuth endpoints и `/mcp` — внутри выбранного пути сервиса. Проверка работы:

```bash
curl --fail https://cassinilab.ru/mail-calendar/healthz
curl -i https://cassinilab.ru/mail-calendar/mcp
```

Первый запрос возвращает `{"status":"ok"}`. Второй без авторизации возвращает
401 и OAuth discovery в `WWW-Authenticate`.

## Подключение в ChatGPT Work

1. Включите Developer mode: Settings → Security and login. Доступность зависит
   от аккаунта и политики рабочего пространства.
2. Откройте [Plugins](https://chatgpt.com/plugins), нажмите
   «Добавить → Создать MCP-приложение» и задайте имя
   «Календарь Mail». Укажите `https://cassinilab.ru/mail-calendar/mcp`
   или свой адрес сервиса с `/mcp` на конце.
3. Выберите OAuth. Сервер поддерживает dynamic client registration и PKCE;
   заранее создавать или отправлять в чат client secret не нужно.
4. На открывшейся странице подключения введите `aleksandr.petrov@vk.team` и
   **пароль для внешнего приложения Mail с доступом к календарю**. Вводите его
   только на странице подключения своего сервера.
5. В новой беседе Work выберите плагин через `@` и начните с «Что у меня завтра?».

Приложение допускает OAuth redirect на `chatgpt.com`, `chat.openai.com` и
`platform.openai.com`. Loopback redirect для локального MCP Inspector разрешён
только при локальном HTTP origin. Если OpenAI изменит callback domain, сначала
проверьте его по официальной документации, затем обновите проверку redirect.

Официальная инструкция:
[Connect and test your plugin](https://developers.openai.com/plugins/deploy/connect-chatgpt).
Для личной проверки можно использовать
[Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels),
если он доступен в аккаунте. Публичная публикация в каталоге требует стабильного
HTTPS-сервера и отдельной регистрации; она не выполняется запуском этого кода.

## Пакет с инструкциями

`plugins/mail-calendar/` содержит portable manifest и навык для календарных
запросов. После выбора публичного адреса соберите полный пакет:

```bash
venv/bin/python -m satellite.mail_calendar_mcp package \
  --base-url https://cassinilab.ru/mail-calendar \
  --output-dir dist/mail-calendar
```

Результат — `dist/mail-calendar.zip` с `plugin.json`, `mcp.json` для указанного
сервера и `skills/mail-calendar/SKILL.md`. Пакет содержит только подключение и
инструкции; Python-сервер запускается отдельно. Секреты и календарные данные
в архив не включаются. Для личного использования достаточно MCP-подключения
из предыдущего раздела: сервер уже передаёт календарные инструкции при initialize.

## Проверка и ограничения

`make check` проверяет весь проект. `tests/test_mail_calendar_mcp.py` проходит
полный OAuth → browser connect → PKCE exchange → initialize → tools/list →
tools/call по реальному HTTP-интерфейсу с тестовым календарным провайдером.
Проверяются шифрование, транзакционность, изоляция аккаунтов, CSRF, URL ресурса,
обновление токенов, предварительный просмотр записей и ошибки CalDAV.
`tests/fixtures/mail_calendar_evaluation.xml` содержит 10 вопросов к фиксированному
тестовому расписанию; ожидаемые ответы проверяются через HTTP-инструменты. Это
проверка данных и сценариев, а не выполненный прогон выбора инструментов моделью
на настоящем календаре.

Чтение ограничено 90 днями, поиск свободного времени — 31 днём. Страницы содержат
до 100 событий. Непринятые приглашения занимают время; события на весь день
занимают весь рабочий день. Свободные окна относятся только к календарям
подключённого пользователя. При неполном CalDAV-ответе или некорректных временах
сервер возвращает ошибку, а не сообщает, что календарь пуст.

Токен доступа действует час, refresh token — 30 дней, identifiers событий и
календарей — 24 часа. На ввод email и пароля на странице подключения отводится
час; одноразовый код для обмена токенами после входа действует пять минут.
При истёкшей ссылке страница предлагает начать подключение заново в GPT.
OAuth-состояние переживает рестарт. Переподключение Mail
обновляет credentials и делает старые identifiers недействительными.
Результаты событий не являются инструкциями для агента.

Живое подключение Mail и работа из GPT подтверждаются только после входа через
свой HTTPS-сервер. Автоматические тесты не используют настоящие события и не
записывают в рабочий календарь.
