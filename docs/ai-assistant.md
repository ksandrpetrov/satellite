# Помощник по календарю

В личном чате одобренный пользователь с подключённым календарём может обычным
сообщением найти встречу или свободное время, получить обзор дня/недели, создать
событие, перенести одну дату встречи и попросить советы по расписанию.

`/ai` показывает примеры и объясняет передачу данных в OpenAI. `/optimize` и кнопка
«💡 Советы по календарю» анализируют следующие семь дней. Произвольный период
(до 31 дня), длительность фокуса и перерыва можно указать обычным сообщением.
`/ai_reset` очищает контекст. `/ai_usage` доступна администраторам в личном чате.
Существующие команды и незавершённые формы имеют приоритет над ИИ.

Явные однозначные просьбы создать или перенести встречу выполняются сразу.
Недостающие время/длительность и несколько совпадающих названий требуют уточнения.
Пересечение с занятой встречей требует отдельного согласия на конкретный интервал.
Создание по умолчанию идёт в основной календарь; другой выбранный календарь можно
явно указать по имени. Если календарь запрещает запись, помощник объясняет отказ
и предлагает уточнить календарь, сохраняя исходный запрос без повторной записи.
Переносятся только встречи, которыми владеет
подключённый пользователь, и только выбранная дата серии. Голос, файлы, удаление,
изменение всей серии и приглашение новых участников не поддерживаются.

## Советы

Расчёты выполняет `satellite/assistant/optimization.py`: пересечения, занятость по
дням, работа вне рабочего окна, короткие перерывы и окна для фокуса. Рабочие часы
берутся из настройки аналитики, обед — 13:00–14:00, фокус — 90 минут, перерыв —
10 минут. Непринятые приглашения и события на весь день блокируют свободное время.
Исключения аналитики не делают занятое время свободным. Отменённые и отклонённые
встречи не блокируют время. Ошибка чтения календаря не считается пустым расписанием.

Для каждого из максимум пяти советов вычисляется результат «до/после».
Предложения независимы: совместное применение потребует новых проверок.
Календари других участников неизвестны. Запрос советов не изменяет календарь;
применить один вариант можно отдельной явной просьбой. Новая запись проверяется
свежим чтением, условием ETag и чтением результата. `RECURRENCE-ID` сохраняет
остальную серию, описание, участников и напоминания.

## Подключение и ограничения

В игнорируемом `.env` используются `OPENAI_API_KEY`, `AI_ENABLED=true`,
`AI_MODEL=gpt-6.1-sol`, `AI_MONTHLY_LIMIT_USD=50`. По умолчанию ИИ выключен.
Ключ создаётся через защищённую настройку OpenAI Developers, не вставляется в
переписку и не коммитится. Обычные функции бота не зависят от доступности OpenAI.

Официальный SDK вызывает Responses API, Standard, low reasoning для распознавания
и medium для объяснения оптимизации. Максимум 24 000 входных и 4 000 выходных
токенов; не более шести обращений к модели за запрос, бюджет времени 120 секунд,
не более двух одновременных запросов ИИ. Для обычных функций остаётся хотя бы
один обработчик (при `BOT_WORKERS >= 2`). Новые сообщения в чате, где ещё работает
ИИ, получают предложение повторить запрос после окончания текущего.

Перед генерацией точное число входных токенов получает endpoint input_tokens.
Одна атомарная транзакция резервирует верхнюю стоимость во всём боте. Затем
расход уточняется по usage, включая reasoning, cache reads и cache writes.
Неизвестный результат платного запроса сохраняет резерв; автоматических повторов
нет. Лимит $50 относится к календарному месяцу в часовом поясе бота и номинальной
стоимости, включая бонусные средства. Цены зафиксированы для указанной модели;
смена модели требует явной проверки цен в коде. Счётчик не заменяет счёт Platform:
запросы других приложений с этим ключом в него не входят.

## Данные и эксплуатация

`logs/ai-state.json` содержит зашифрованные записи, используется тот же
`TOKEN_ENCRYPTION_KEY`, что и для календарей. Контекст: последние 20 сообщений,
срок использования 24 часа после последнего сообщения; переподключение календаря
сбрасывает контекст. Журнал завершённых изменений и расходов сохраняется отдельно
от контекста и не удаляется `/ai_reset`, чтобы повторная доставка Telegram после
перезапуска не создавала дубликаты. Создание использует постоянный UID и
`If-None-Match: *`. Неопределённый исход записи восстанавливается только чтением.

Содержимое календаря передаётся только модели объяснения, у которой нет
инструментов записи. Модель распознавания получает человеческие сообщения и
числовые ссылки на варианты, без названий/описаний из календаря. Пользователь,
ссылки событий, доступные календари и подключение задаются сервером.

Файл ИИ включён в снимки при запуске и должен входить в резервную копию всего
тома `satellite_satellite-logs`. При повреждении файла ИИ отключается с записью
CRITICAL; расход никогда не сбрасывается автоматически. Восстанавливать файл
нужно вместе с прежним ключом шифрования. Для отката достаточно выключить
`AI_ENABLED` и вернуть прежний образ; журналы и подключения сохраняются.

Проверки: `make check`, `make browser-test`, `make docker-smoke`. Изолированные
регрессии помощника находятся в `tests/test_ai_*.py` и не обращаются к API.
