# Продуктовое качество и доступность — 29 сентября 2026

Проверка и исправления выполнены на изолированном стенде. Реальные аккаунты,
production-данные и отправка сообщений не использовались. Пользовательская правка
`deploy/ansible/inventory.yml` сохранена. Коммита и деплоя в рамках аудита нет.

## Метод и исходная точка

До изменений: `make check` — **1353 passed**, все статические проверки зелёные;
браузерный набор — **12 passed**, только Chromium. Новый аудит продолжает
[проверку корректности данных 26 сентября](product-correctness-audit-2026-09-26.md).

Сначала добавлены воспроизводящие проверки, затем исправлены причины ошибок.
На исходном коде получены падения 7 браузерных случаев (черновик, доступность,
подтверждение времени, ложный успех, отмена незавершённой записи), 4 HTTP-случаев
(UID и переполнение даты), 4 случаев создания в боте (DST и полночь).
Отдельно воспроизведены ошибки объявления валидации, пустого ответа списка,
подсказки после отключения и конкурирующих действий подключения.
Добавлено 16 случаев основного набора и 23 браузерных случая. Вместе с прежними
12 браузерными случаями они дают 35 на движок, 70 на версию Python.
Существующие проверки не ослаблялись, skip/xfail не добавлялись.

Дополнительно проверена запись повторного осеннего часа через API → настоящий
локальный CalDAV PUT → сохранённый ICS (`test_repeated_dst_hour_survives_api_and_real_caldav_write`):
30/60 минут от первого 01:30 сохраняются как 05:30Z–06:00Z/06:30Z.
Сравнение границ выполняется в UTC, чтобы правильный конец в повторном часе
не отклонялся из-за локального порядка часов.

Дополнительно закреплены проверки устойчивости:

- Из двух ответов списка применяется только результат последнего запроса:
  `test_stale_events_response_cannot_overwrite_newer_list`.
- У fetch есть предел ожидания 30 секунд; при неопределённом результате записи
  предлагается проверить календарь перед повтором. Автоматического повтора записи
  нет: `test_slow_write_times_out_without_claiming_failure_or_losing_draft`.
- Медленное построение плана пользователя 1 не задерживает отправку пользователю 2;
  durable markers выставляются после результата, затем завершается первый план:
  `test_slow_plan_does_not_delay_other_users_delivery`.
- Текст ошибки подписи сессии больше не предлагает пользователю править `.env`
  и токен сервера; он ведёт к повторному открытию окна из бота.

## Аудит интерфейса по HIG

Ориентиры: Apple [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility),
[Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) и
[Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback).
Применены к Web App с учётом ограничений HTML и Telegram; это не сертификация Apple.

- Области нажатия основных контролов — минимум 44 CSS px по высоте.
- Ширины 320/390/430 px, увеличение текста до 200%, длинное название: без
  горизонтальной прокрутки; кнопки и вкладки перестраиваются при нехватке места.
- Добавлены тёмная fallback-тема, safe-area отступы и видимый keyboard focus.
- Контраст основного текста, подсказки и кнопок fallback-тем проверяется численно:
  минимум 4.5:1 в обеих темах. Измеряется фон корневого canvas и видимые элементы;
  WebKit возвращает для body прозрачный computed background, хотя canvas тёмный.
- `prefers-reduced-motion` останавливает spinner; проверено в обоих движках.
- Загрузка и ошибки имеют текстовое объяснение; неопределённый результат не
  превращается в ложный успех. Новый текст хранится в `messages_ru`.

Скриншоты и трассы сохраняются в игнорируемом `test-results/`:
`layout-{chromium,webkit}-{320,390,430}-{light,dark}.png`,
директории сценариев с `screen.png` и `trace.zip`.
Просмотрены мобильные формы/подтверждения и темы; численные и функциональные
проверки выполняются в каждом варианте матрицы.

## Контракты и ограничения

- Формат хранилищ и структура публичных API не меняются. Исправления контрактов:
  корректный исходный UID на DELETE, 400 вместо 500 для переполнения даты,
  отклонение несуществующего местного времени; duration означает реальное
  прошедшее время. HTTP datetime без offset трактуется в настроенной зоне сервера.
- Неоднозначный осенний час без offset использует первое вхождение (`fold=0`);
  API с явным offset сохраняет его. При смене offset подтверждение показывает
  оба UTC-смещения, включая встречу 01:30 (UTC-04:00) → 01:00 (UTC-05:00).
  Выбор второго вхождения отдельным контролом не добавлялся.
- Переключение вкладок сохраняет черновик в текущем окне. Перезагрузка/закрытие
  страницы не сохраняет его на диск.
- Таймаут браузера не отменяет уже выполняющуюся запись на сервере. Проверка
  результата перед ручным повтором обязательна; сквозной idempotency key между
  независимыми HTTP-запросами не добавлен.
- Дедуп доставки при сбое сохранения marker защищает текущий процесс; гарантия
  exactly-once через аварийный рестарт и внешнюю сеть не заявляется.
- Применение пользовательских Telegram theme variables сохранено. Контраст
  произвольных сторонних тем и реальное озвучивание VoiceOver не проверялись.
- WebKit на macOS не заменяет Telegram WebView на iPhone, системную клавиатуру,
  VoiceOver и проверку на реальном устройстве. Живые Telegram/CalDAV и discovery
  внешних провайдеров остаются за пределами согласованного стенда.
- Docker smoke не выполнен: установленный CLI не смог подключиться к daemon
  (`~/.docker/run/docker.sock` отсутствует). Linux CI изменён для
  обоих браузеров, но удалённый workflow в этой сессии не запускался.
