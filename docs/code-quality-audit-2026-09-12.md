## Исправления и доказательства

- `lock-check` завершает работу при любой ошибке компиляции/сравнения, а не только
  возвращает код последней команды. `test_lock_check.py` исполняет настоящий Makefile
  с fake uv: обе ошибки компиляции, оба расхождения, успешный случай и сохранность
  исходных lock-файлов. Сеть для этого теста не нужна.
- `HandlerRuntime` принадлежит экземпляру бота. Его guards, списки календарей,
  снимки исключений и трекер хаба не передаются другому боту или тесту. Scheduler
  получает тот же `EventTokenCache`, что хендлеры. Проверены реальные конструкторы
  двух ботов, повторная сборка контекста и дедуп действий.
- Общий `UserCache` заменил три реализации TTL-кэшей; удаление истёкшей записи
  выполняется под тем же lock, что чтение, и не может удалить свежую замену между
  чтением и удалением. TTL 60/600 секунд и LRU-лимит исключений 128 сохранены.
- `EventTokenCache` сериализует составные изменения. Регрессия с двумя потоками
  проверяет, что два ответа не возвращают уже удалённое приглашение в список.
- Dispatcher не отмечает отменённую задачу или задачу с необработанным исключением
  выполненной. Семaфор освобождается при любом исходе. Проверены все три исхода и
  невозможность продвижения durable offset через незавершённую задачу.
- Невалидный UTF-8 в users/subscriptions приводит к публичной load-ошибке,
  обрабатываемой существующей границей запуска. Некорректный root/offset и отрицательный
  offset восстанавливаются в 0 по политике `OffsetStore`. Восемь сценариев воспроизвели
  ошибки до правки и прошли после; файлы при чтении не переписываются.
- Обновление daily/pending настроек принимает явные `enabled`, `days`, `time`.
  Строковые имена атрибутов и произвольные kwargs удалены. Тест с настоящим store
  проверяет сохранность второго дайджеста, непереданных полей и повторную загрузку.
- Строгий mypy дополнительно включён для runtime, ActionGuard и EventTokenCache.

## Удалённые и упрощённые тесты

- Удалены 6 runtime- и 5 dev-проверок отдельных прямых пинов: полное равенство наборов
  в `test_dependency_inputs_contain_only_direct_pins` уже проверяет каждое вхождение
  и отсутствие лишних зависимостей. Проверки пинов в generated locks сохранены.
- Удалён `test_reset_clears_state` вместе с `ActionGuard.reset`: метод обслуживал
  исключительно старую глобальную фикстуру. Изоляцию теперь проверяют тесты runtime
  и двух экземпляров бота. Убран также неиспользуемый `EventTokenCache.reset`.
- Глобальные autouse-reset фикстуры удалены. Фабрики mock-контекстов создают настоящий
  `HandlerRuntime`; бизнес-assertions сохранены.
- Проверка мёртвых строк сканирует корпус один раз через Counter вместо одного
  сканирования на каждую константу. Критерий лексических ссылок прежний.
- Проверка истечения cooldown использует управляемые часы вместо реального sleep.

## Воспроизводимость и оставшиеся ограничения

`make coverage` доступен после установки requirements-dev.txt. Добавлен только
`coverage==7.15.2`; runtime-lock не изменён. `make lock LOCK_UPGRADE=` позволяет
добавлять зависимость с сохранением остальных версий; обычный `make lock` по-прежнему
обновляет допустимые версии. `make lock-check` проверяет результат.

Docker smoke проверяет импорты всех модулей, установленную версию caldav и настоящий
HTTP `/healthz` внутри read-only контейнера без пользовательских credentials.
Release gate — полный `make check`, Docker smoke и CI Python 3.11/3.12.

Покрытие остаётся неполным прежде всего в живом discovery/HTTP CalDAV, Telegram API,
ветвях запуска и логировании. Тесты используют контролируемые ответы сервисов;
поведение внешних провайдеров и доставку без повторов при падении процесса эти
замеры не доказывают. Формат хранения и протокол подтверждения Telegram updates
не перерабатывались. Не следует удалять оставшиеся интеграционные проверки только
из-за пересечения с unit-тестами: они проверяют соединение слоёв.
